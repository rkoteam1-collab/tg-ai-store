# Перенос AIshopify на сервер в РФ

Эти файлы готовят запуск магазина на одном российском VPS с постоянным диском и HTTPS. Сами по себе они **не подтверждают локализацию**: нужны фактический сервер в РФ, его настройки и проверка места хранения резервных копий и логов. До переключения нельзя заменять в политике указание текущего Render (Oregon) на утверждение о российском размещении.

1. Получить VPS в РФ, проверить расположение его диска и резервных копий, привязать домен к IP. Открыть входящие TCP 80/443. Не размещать секреты в Git.
2. Скопировать репозиторий на VPS. Создать `deploy/.env` с `PUBLIC_HOST=домен` и `deploy/server.env` с секретами из `.env.example`. Эти файлы не должны попадать в репозиторий. Для первого запуска без уже оплаченных заказов разрешается пустое хранилище; при существующих заказах обязательно сначала перенести фактические данные работающего Render, а не seed-файлы из Git.
3. Из каталога `deploy` выполнить `docker compose --env-file .env up -d --build`. Проверить `https://домен/api/health`, каталог, админские изменения после перезапуска контейнера и создание тестового неоплачиваемого заказа только в согласованном с платёжным провайдером тестовом режиме. Убедиться, что том `shop_data` сохраняется и резервные копии остаются в РФ.
4. Установить `BACKEND_URL`, `WEBAPP_URL`, `FRONTEND_URL` равными новому HTTPS-адресу (compose задаёт их из `PUBLIC_HOST`). Перед переключением Telegram-бота и IT-Pay обновить их webhook-адреса и проверить подписи и доступность. Не запускать одновременно два процесса, которые пишут в один JSON-каталог.
5. Сменить адрес API в `.github/workflows/storefront-pages.yml` или перевести Telegram-меню на новый сайт целиком. При полном переносе на VPS обновить резервные ссылки на Render в `index.html` и `src/main.jsx`, проверить, что браузер больше не передаёт персональные данные на Render. Затем обновить публичную политику фактическими адресами и обработчиками.
6. Подтвердить наличие уведомления Роскомнадзору об обработке ПД и отдельно оценить уведомление о трансграничной передаче для нужных подрядчиков. Документы и техническое размещение решают разные задачи: одна запись в РФ не разрешает автоматически любую дальнейшую зарубежную обработку.

Команда ниже только собирает образ; фактический запуск требует VPS и настроенных секретов. Платежи на старом Render не следует отключать или переключать до проверки нового сервера и сохранения текущих заказов.
